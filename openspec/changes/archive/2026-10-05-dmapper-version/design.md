# Design

## Context

Today (2026-10-05, after `retire-core`):
- `CMakeLists.txt` defines `HDMAPPING_VERSION_MAJOR/MINOR/PATCH` = 0, 95, 0 with `add_definitions`, and adds `shared/include` with `include_directories` for every target.
- `shared/include/HDMapping/Version.hpp` builds `HDMAPPING_VERSION_STRING` ("v0.95.0"). It is used by `folder_result_sink.cpp` (`lidar_odometry_version` in the results JSON); `lidar_odometry_gui.cpp` and `viewer.cpp` include it without using it.
- `odometry_config.h`'s `get_software_version()` builds "0.95.0" from the macros, as the default of `OdometryConfig::software_version`.
- `software_version` and `config_version` are in `TomlIO::POINTERS`, so loading a parameter file overwrites them. `folder_result_sink.cpp` names the files `HDMapping_params_<config.software_version>_<date-time>.toml` and `HDMapping_results_…json` and writes `software_version` into the JSON's `processing_info`. `TomlIO` writes `# Generated by HDMapping v<version>` and the `[version_info]` section, and on loading compares the file's version with `get_software_version()` (a warning when major or minor differ).
- `settings/default_settings.toml`, `settings/lidar-vertical.toml` and the golden test files say `software_version = "0.95.0"`.
- `tools/compare_baseline.py` matches `HDMapping_params_*.toml` and `HDMapping_results_*.json` and strips their date-time; `tools/eval_odometry.py` globs `HDMapping_results_*.json`. The manifests list file names and contents.

## Goals / Non-Goals

**Goals:**
- One version, 0.1.0, set once in `CMakeLists.txt`, in the outputs' names and contents and in the GUI title.
- A run's recorded version is the build's, whatever the loaded file says.
- No `shared/` folder, no global include path for it.

**Non-Goals:**
- `config_version` (the settings format, "1.0") and the compatibility rule stay.
- The processing and every data file stay identical.

## Decisions

1. **`src/domain/dmapper_version.h`:**
   ```cpp
   // dMapper's version, set in the top-level CMakeLists.txt (DMAPPER_VERSION_MAJOR/MINOR/PATCH)
   inline std::string dmapper_version();       // "0.1.0"
   inline std::string dmapper_version_short(); // "0.1", for the window title
   ```
   It `#error`s when the macros are missing, as `Version.hpp` did. It is in the domain because `odometry_config.h` needs it for its default; infrastructure and the GUI reach it through `lo_domain`'s public include directory. `CMakeLists.txt` defines the macros with `add_definitions` in place of `HDMAPPING_VERSION_*`.

2. **The build's version wins:** `TomlIO`, after loading a file, sets `params.software_version = dmapper_version()`. The file's own `[version_info]` is still read separately for the compatibility warning. The round-trip test that expected a loaded `"test-version"` now expects the build's version.

3. **Names and texts:** `dMapper_params_` / `dMapper_results_` in `folder_result_sink.cpp` (and its header comment); `lidar_odometry_version` = "v" + `dmapper_version()`; `# Generated by dMapper v…` in the TOML header; the loading messages say "dMapper" where they say "HDMapping". The GUI's `winTitle` becomes `"dMapper v " + dmapper_version_short()`.

4. **TOML files:** `settings/*.toml` get `software_version = "0.1.0"` in `[version_info]` (one line each; nothing else in them changes). The golden test files are regenerated with `LO_UPDATE_GOLDEN=1`, in their own commit, as `CLAUDE.md` prescribes.

5. **Tools:** `compare_baseline.py`'s patterns become `dMapper_params_*.toml` / `dMapper_results_*.json`, and `eval_odometry.py`'s glob `dMapper_results_*.json`.

6. **Proving that only the version changed, then new baselines.** Before any manifest is replaced:
   - run the new build on `44_short` (normal and precise) and compare with the current manifests: every file except the two version-stamped ones must be IDENTICAL;
   - diff those two files against the baseline folder's versions with the version strings and date-times masked: no other line may differ.
   Then, in one commit of their own: new `tools/baseline/44_short.manifest.json` and `44.manifest.json` (from the full 44 run), a new precise manifest in the scratchpad, and new `raw data/44_short_baseline` / `raw data/44_baseline` folders (the old ones kept as `*_2026-10-05`).

7. **Commit order:** (1) the version header, CMake, the code and the settings files (the step check can only compare data files here, design 6); (2) the golden files; (3) the tools; (4) the new baselines with the full 44; (5) the docs.

## Risks / Trade-offs

- **[A data file changes]** e.g. `session.mjs` naming the params file. → Decision 6 catches it before the baseline is replaced; if a data file other than the two changes, the cause is recorded and reported.
- **[Old parameter files warn]** Files from HDMapping 0.95 now warn about a version mismatch when loaded. → Intended: they come from another program; the run is unaffected.
- **[The precise reference]** Its manifest also names the files. → Made again with the others (decision 6).
