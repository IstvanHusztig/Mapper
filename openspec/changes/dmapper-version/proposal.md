# Proposal

## Why

The GUI calls itself "dMapper v 0.1", but every result still carries HDMapping's version: the build defines `HDMAPPING_VERSION_*` = 0.95.0, and the output folder holds `HDMapping_params_0.95.0_<date-time>.toml` and `HDMapping_results_0.95.0_<date-time>.json` with "0.95.0" / "v0.95.0" inside. Worse, the version in those names doesn't even come from the build: `software_version` is an ordinary setting, so the loaded parameter file decides it (`settings/lidar-vertical.toml` says 0.95.0). The version header itself sits in a leftover HDMapping layout, `shared/include/HDMapping/Version.hpp`, on a global include path.

The user decided (2026-10-05): the outputs take dMapper's version, the two files are named `dMapper_…`, and the `shared/include/HDMapping/` nesting goes.

## What Changes

- **One version, set in the build:** `CMakeLists.txt` defines `DMAPPER_VERSION_MAJOR/MINOR/PATCH` = 0.1.0 in place of `HDMAPPING_VERSION_*`. A small header `src/domain/dmapper_version.h` turns them into `dmapper_version()` ("0.1.0") and `dmapper_version_short()` ("0.1"). `shared/` and `include_directories(shared/include)` go.
- **The results carry the build's version:**
  - `dMapper_params_0.1.0_<date-time>.toml` and `dMapper_results_0.1.0_<date-time>.json` replace the `HDMapping_*` files;
  - inside them, `software_version` is "0.1.0", the results JSON's `lidar_odometry_version` is "v0.1.0", and the params file's header comment says "Generated by dMapper";
  - loading a parameter file no longer sets the version: its `[version_info]` is only compared with the build's, for the existing compatibility warning.
- **The GUI title comes from the same source:** "dMapper v " + `dmapper_version_short()`, still exactly "dMapper v 0.1".
- **The shipped and golden TOML files** say 0.1.0 in `[version_info]`, so loading them gives no version warning.
- **Tools and baselines:** `compare_baseline.py` and `eval_odometry.py` match the `dMapper_*` names; the 44 and 44_short manifests, the precise manifest and the two baseline folders are made again from this build. Every data file (LAZ, trajectories, poses, point sizes, `session.mjs` paths) must stay byte-identical; only the two version-stamped files change, and only in their name and version fields.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `processing-pipeline`: a new requirement, "Results carry dMapper's version".
- `regression-baseline`: "Run-dependent fields are normalized" names the `dMapper_params_*` / `dMapper_results_*` files.

## Impact

- **Code:** `CMakeLists.txt`; new `src/domain/dmapper_version.h`; `src/domain/odometry_config.h` (`get_software_version`); `src/infrastructure/folder_result_sink.{h,cpp}`, `toml_io.{h,cpp}`; `src/presentation/gui/lidar_odometry_gui.cpp`, `viewer.cpp` (an unused include); `shared/` deleted; `tests/toml_config_repository_test.cpp`; the golden TOML files; `settings/*.toml`.
- **Tools:** `tools/compare_baseline.py`, `tools/eval_odometry.py`, `tools/README.md`; new baseline manifests and baseline folders.
- **Docs:** `CLAUDE.md` (Build: the version; Testing: the file names), `docs/` mentions of the `HDMapping_*` files.
- **Not changed:** the processing and its numbers; `config_version` ("1.0", the settings format); the `session.mjs` format.
