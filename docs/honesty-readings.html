Honesty readings and truth tests: is the estimator as sure as it says?

Every window hands its velocity, acceleration offset and gyro bias to the next one together with a covariance: a claim of how well it knows them. If that claim is too confident, the next window trusts a wrong value and a later correction comes as a jump. This page describes the instruments that check those claims: readings in every run, and tests on synthetic data whose truth is known. It says how to get them, how to read them, and what they do not say. They change no result.

Terms used here: window, hand-off, prior, sigma and information, velocity, acceleration offset, gyro bias, velocity chi², normalised move, window verdict, per-term table, capture and replay. All basic terms: the guide's Fundamentals.

The normalised move

For a carried state with prior mean m and prior covariance P, a window finds the result x and the posterior covariance Ppost. Under the window's own model the move d = x − m has the covariance P − Ppost, so

q = dT P-1 d / (n − tr(P-1 Ppost))      expected value 1

with n the state's dimension. q near 1: the window moved the state about as far as its claim allows. q of 9: the moves are about 3 times larger (in sigma) than claimed. q well below 1: the claim is more cautious than needed. Three states are read: the start velocity (every window with the accelerometer term), the start velocity and offset jointly (with imu_carry_joint_covariance), and the gyro bias.

Why not the velocity chi²?The velocity chi² divides the same move by P alone. That statistic's expected value is not 3 but 3 − tr(P-1Ppost), between 0 and 3, and about 1 at rest, so it understates how far off a claim is. The chi² and its agreed limits stay as they are; the normalised move is reported beside it.

NOT MEASURED replaces the number when the reading would not mean anything:

How to get and read them

Every run and replay writes three summary lines, with their coverage even when nothing was measured:

window verdict summary: normalised move, start velocity (descriptive, 1 expected under the window's own model): coverage 84/84, median 13.060, p95 61.320, largest 96.570
window verdict summary: normalised move, start velocity and offset (descriptive, ...): coverage 0/84; not measured: absent 84
window verdict summary: normalised move, gyro bias (descriptive, ...): coverage 0/84; not measured: reduction below 0.5 84

With log_window_verdict = true a flagged window's line ends with its three readings. With log_window_terms = true each window's row in window_features.csv has move_start_velocity, move_joint and move_gyro_bias, each with _reason and _reduction (the denominator). Find where along a route the claims break by plotting move_start_velocity against time_s next to the information_ratio.

What a reading does not sayThe readings are descriptive. The posterior is conditional on the window's first pose being exact, the weights are re-weighted (Huber) and the problem is linearised, so 1 is a model expectation, not a guarantee. A reading far above 1 shows a claim that the window's own data contradicts; it does not say which term is wrong, and it says nothing about the map. There are no limits and no triggers on these readings.

The prepared and handed-on state

With log_window_terms, each window's row of window_features.csv also holds:

  • prepared_*: the first pose as the window was placed, and the priors it was prepared with (velocity, offset, their cross covariance as its diagonal, gravity vector, gyro bias), each with its sigmas.
  • handoff: done, or cancelled when the run stopped at this window.
  • handed_*: what it gave the next window, taken after the hand-off: end velocity, gravity vector after the offset was folded in, the unit factor before the fold, offset and bias with sigmas, and the last node as solved and after the tail was re-propagated (handed_last_solved_*, handed_last_*).
  • rotation_rate_mean_deg_s (from the attitude increments) and start_acceleration_* (the world-frame acceleration over the window's first 30 ms).

A window's prepared_first_* against the previous row's handed_last_* shows the hand-off; handed_last_* against handed_last_solved_* shows what the tail re-propagation moved. The earlier columns of the file are unchanged.

The truth tests

The readings show that a claim does not fit. To find why, the unit tests run the production code on synthetic data whose truth is known, in a "model world" where every sensor error is drawn as the estimator's weights assume. A failure is called an error of the code only where a test isolates one quantity and states the honest outcome; everything measured on the whole loop is reported as a measurement.

out\build\x64-Release\bin\lidar_odometry_tests.exe -tc="exact control*"

Writing a new case

  • Make a recording: generate_recording(route_r2(), SensorProfile{...}, ImuNoise{}) (ImuNoise::none() for noise-free), and cut it with cut_into_windows through the real front end. For a single window, a hand-built analytic window is simpler and exact.
  • Run the real loop with start_window_loop and process_windows, a carried state you set yourself, and log_window_terms with a sink that keeps the records; read prepared and handed_on.
  • Pair every measurement with a control that differs in one thing only.
  • Statistics: truth_stats::normalised_error, chi2_interval, runs_for_power (how many runs a stated deviation needs); fix the instant, the axis and the decision rule before sampling, and never pool the windows of one run as independent draws.
  • Mark a case doctest::should_fail only when the discrepancy is reproduced, isolated, and an independent statement says what the honest outcome is; otherwise report it.

What they have shown so far

Measurements of 2026-11-20, no verdicts.

  • Start-velocity normalised move on replays: median 13 (an indoor Livox stretch) and 41 (an L2 stretch). The velocity's moves are several times larger than its claimed sigma; the gyro bias's reading is almost never measurable.
  • All seven unit cases reproduce the predictions of the audit, each isolated by its control.
  • New: a window at steady speed without acceleration passes the rest test and, with imu_always_on, is solved as at rest (end velocity 0.01 m/s for a true 2 m/s).
