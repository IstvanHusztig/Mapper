# Correcting Unitree L2 reflectivity

Getting correct reflectivity from the Unitree L2 is a measurement problem that has to be solved on this unit's own data, because **nothing published defines what its 8-bit intensity is**. The open SDK copies the raw `uint8` "Point Reflect [0-255]" straight into `intensity` with no range, angle or other compensation. Unitree documents no scale, no range compensation, no gain control and no near-range behaviour, and no paper or community test of L1/L2 intensity was found. The workable route has four steps. First, characterise the byte with a few cheap tests: histogram, saturation, intensity against range on one patch, the near-field, and gain stability. Second, model the return as an empirical product, raw = G[g(R)·h(α)·ρ], where the range curve g(R) is fitted in log space and dense below 2 m, and the incidence curve h(α) is cosine or Oren–Nayar using normals taken from the final multi-pass map. Third, filter mixed pixels, saturated values, grazing angles and mist. Fourth, solve for the curves by **targetless self-calibration from dMapper's own multi-view observations**, with a small reflectance-panel grid to anchor the absolute scale and to validate. Published corrections reach **<3 % to ~10 % of true reflectance on survey-grade TLS**. For a low-cost 905 nm sensor whose returns are mostly within 5 m (the near-field zone), 5–15 % relative residual is a realistic goal. That figure is an inference, not a measurement. dMapper suits the job because loop closure and consistency already give final poses and dense revisits of each wall. Today, though, it discards the per-point range, incidence angle and sensor position the correction needs. Material identification comes later and depends entirely on this step.

**Evidence note.** Unitree SDK code, Mandeye code and dMapper code were read directly. Unitree manual statements are search extracts. Most papers were read only as abstracts, bibliographic records or search extracts, because publisher sites were blocked during research. Formulas marked "standard form" were not checked against the full text. Items marked *(inference)* are reasoning that no source tested. Items marked *(computed)* are derived here.

## The L2 byte is undefined until five tests pin it down

The L2 packet struct `LidarPointData` holds `uint16_t ranges[300]` (mm) and `uint8_t intensities[300]`, commented only as "Point Reflect [0-255]". Its calibration parameters `range_bias` and `range_scale` correct range, and nothing corrects intensity ([unilidar_sdk2 protocol header](https://raw.githubusercontent.com/unitreerobotics/unilidar_sdk2/main/unitree_lidar_sdk/include/unitree_lidar_protocol.h)). In `parseFromPacketToPointCloud`, **`point3d.intensity = intensities[j]` is a direct copy**, and `ring` is hard-coded to 1, so the L2 exposes no per-emitter channel ([unilidar_sdk2 utilities](https://raw.githubusercontent.com/unitreerobotics/unilidar_sdk2/main/unitree_lidar_sdk/include/unitree_lidar_utilities.h)). The manual describes the field only as "the reflectivity of the detected object" and the sensor as "3D position + 1D gray level" (search extract, [L2 User Manual](https://oss-global-cdn.unitree.com/static/Unitree%204D%20LiDAR%20L2%20User%20Manual.pdf)). Its specs are quoted at 25 °C with a 90 % target at 15 m (search extract, [Manuals+ copy](https://manuals.plus/unitree/4d-lidar-l2-from-robotics-to-infrastructure-manual)). A "Reflective Surface Performance Guide" exists, but its content could not be retrieved ([ManualsLib](https://www.manualslib.com/manual/3616985/Unitree-4d-Lidar-L2.html?page=5)). One unsourced marketing blog claims that the L2 "dynamically adjusts laser power to prevent saturation" ([AliExpress wiki](https://www.aliexpress.com/s/wiki-ssr/article/lidar-4d)). If that is true, raw intensity is non-stationary. Automotive practice then calibrates each power level separately, with its own gain and bias ([US 11067676](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/11067676)).

Comparable sensors span the possible cases. Livox maps 0–150 to 0–100 % Lambertian reflectance and uses 151–255 for retroreflectors. A Livox staff member says the value is compensated for distance "but the incidence angle", which makes it roughly ρ·cos α (search extract, [livox-lidars group](https://groups.google.com/g/livox-lidars/c/4TphNgFpwZQ)). Livox's own manual warns of "a large reflectivity error" below 2 m (search extract, [Mid-360 manual](https://www.sachtleben-technology.com/wp-content/uploads/sites/5/2024/07/LivoxMid-360UserManual.pdf)). Ouster and Velodyne ship factory range-compensated reflectivity (0–100 linear Lambertian) and correct neither incidence nor near range ([Ouster docs](https://docs.ouster.com/sensor-docs/calibrated-reflectivity), [Amerisurv on Velodyne](https://amerisurv.com/2014/03/19/velodyne-lidar-technology-achieves-calibrated-reflectivies-capability-enables-significant-cost-savings/)). The L2 could therefore be raw return power, a Livox-style compensated value, or a gain-controlled value. **Applying 1/R² to an already compensated value is the classic double-correction error**, so the tests come before any formula ([Kaasalainen et al. 2011](https://researchportal.tuni.fi/en/publications/analysis-of-incidence-angle-and-distance-effects-on-terrestrial-l/) call knowing about reducers and log amplifiers "of cardinal importance").

Along dMapper's path the byte stays intact. dMapper reads LAS `intensity` into `Point3Di::intensity` (`src/infrastructure/recording_folder_source.cpp` l.206). `save_result` passes it unchanged to the chunk and merged LAZ (`src/application/lidar_odometry.cpp` l.551–570, `src/infrastructure/folder_result_sink.cpp` l.60). How dLidar writes the field was not inspected.

**Five tests characterise the byte** *(test designs are inferences built on the mechanisms in the cited literature)*:

1. **Histogram** a whole recording. A maximum of 255 with a pile-up there means saturation. A ceiling below 255, or a comb of missing values, means an internal non-linear mapping.
2. **Intensity against range on one patch.** Walk slowly toward a flat, dry, matte wall at near-normal incidence, from about 15 m down to 0.1 m, and plot the median per 5 cm range bin.
   - A flat curve means the firmware compensates for range.
   - A slope near −2 in log-log means raw power.
   - A peak at a few metres that falls toward zero below about 1 m means near-field optics: the biaxial transmitter/receiver overlap, a brightness reducer, or detector saturation. Kaasalainen et al. found a TLS brightness reducer acting below about 1 m ([TUNI record](https://researchportal.tuni.fi/en/publications/analysis-of-incidence-angle-and-distance-effects-on-terrestrial-l/)).
3. **Angle sweep.** Rotate the sensor through 0–80° at one range. This gives the raw h(α).
4. **Gain stability.** Walk a black and a white target, side by side, through the same ranges. A ratio that changes with range or time means automatic gain or power switching.
5. **Warm-up drift.** Log a static scene for 30 minutes from power-on, against time and temperature.

The same range and angle questions can also be answered retroactively on existing cave recordings. Bin the revisits of one homogeneous wall patch by range at fixed α and fit the slope. Because `ring` = 1, a per-beam Levinson curve cannot be fitted. The beam direction in the sensor frame (azimuth/elevation of the non-repetitive pattern) is the only proxy for a channel *(inference)*.

## Range correction must be empirical, because caves live in the near field

For an extended Lambertian target that fills the footprint, the LiDAR range equation P_r = P_t·D_r²·η_sys·η_atm·σ/(4πR⁴β_t²), with σ = πρR²β_t²cos α, reduces to **P_r ∝ ρ·cos α·η_atm/R²**. The textbook correction to a reference range and normal incidence is I_c = I_raw·(R/R_ref)²/cos α. These are standard forms from Höfle & Pfeifer (2007) and Kashani et al. (2015), with symbols not verified ([Höfle & Pfeifer record](https://heibib.ub.uni-heidelberg.de/search/Record/1885638124), [Kashani et al.](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4701271/)). Targets smaller than the footprint do not follow 1/R². Edges, straws and thin stalactites fall off as 1/R⁴ (point) or 1/R³ (linear), so they must not enter a calibration.

Real instruments break 1/R² at short range, and the fixes in the literature are all empirical:

- **Fang et al.** model a range-dependent "laser transmission function" ([visionbib](https://visionbib.com/bibliography/active672li1.html)).
- **Tan & Cheng** fit I = f₁(ρ)·f₂(cos α)·f₃(R) as least-squares polynomials ([SPIE](https://biomedicaloptics.spiedigitallibrary.org/journals/journal-of-applied-remote-sensing/volume-9/issue-01/094094/Intensity-data-correction-based-on-incidence-angle-and-distance-for/10.1117/1.JRS.9.094094.full)). They find the distance effect "more complex and system-specific" than the angle effect ([PolyU](https://research.polyu.edu.hk/en/publications/intensity-data-correction-for-the-distance-effect-in-terrestrial-/)).
- **Xu et al.** fit separate near and far pieces and, with Oren–Nayar, reach **<3 % of spectrometer reflectance** on a Riegl VZ-400i ([Remote Sens. 9:1090](https://www.mdpi.com/2072-4292/9/11/1090)).
- A **Riegl VZ-1000 cave study** used piecewise polynomials on 2.5–5, 5–15 and 15–60 m ([EGU2020-18742](https://presentations.copernicus.org/EGU2020/EGU2020-18742_presentation.pdf)).

Crucially, Krooks et al. showed that **range and incidence effects do not interact**, which justifies the separable form f(R)·g(α) and lets lab corrections transfer to the field ([ISPRS Annals 2013](https://isprs-annals.copernicus.org/articles/II-5-W2/145/2013/isprsannals-II-5-W2-145-2013.pdf)). No published near-range curve for any 905 nm robotic sensor (Velodyne, Ouster, Hesai, Livox, Unitree) was found.

The working model for the L2 is **I_raw = G[η(R)·ρ·h(α)·η_atm·k(t)/R²]** *(synthesis; inference)*:

- G is the unknown internal mapping (linear, log or vendor-specific).
- η(R) is the near-field factor. It rises from 0 to 1 over the crossover range of a biaxial design and is compressed by any reducer or saturation.
- k(t) is a slow gain term for time, temperature and window state.

Fit **g(R) = η(R)/R² as one spline in log R**, with knots every 0.1–0.2 m below 2 m and sparser beyond, and a monotonicity penalty above the peak. Invert G only if Test 1 or Test 4 shows non-linearity. Only fit g where data exist, and declare everything below the validity limit R_min invalid rather than extrapolating. This matters more in caves than anywhere else. dMapper already rejects points below `min_distance_lidar` = 0.15 m, and much of a narrow passage lies at 0.15–5 m, exactly where a bare 1/R² is badly wrong. Test 2 decides between three shapes: a flat g means "compensated, keep only η", a slope of −2 means "raw", and anything else gets the spline anyway.

## Incidence correction hinges on map normals and an angle cutoff

Lambert's h(α) = cos α is the default, and several TLS studies found it adequate ([Tan et al., PolyU](https://research.polyu.edu.hk/en/publications/intensity-data-correction-for-the-distance-effect-in-terrestrial-/)). Rough rock deviates. Carrea et al. argue that the cosine law is insufficient for rough rock and correct with a simplified Oren–Nayar model that has a single facet-slope parameter ([EGU2015-10643](https://meetingorganizer.copernicus.org/EGU2015/EGU2015-10643.pdf?pdf), [Carrea et al. 2016 record](https://observatorio-cientifico.ua.es/documentos/652b2ab2ebee473633a3aa5a)). Mukupa et al. note that mm–cm irregularities comparable to the spot partly cancel the angle effect ([FIG 2017](https://fig.net:443/resources/monthly_articles/2017/mukupa_etal_september_2017.asp)).

Four model families are in use (standard forms, not verified against the full texts):

| Model | Monostatic form (source = receiver) | Use |
|---|---|---|
| Lambert | h = cos α | matte surfaces, α ≤ 60° |
| Empirical | h = cos^n α | n < 1 rough or flatter-than-Lambert; n > 1 glossy |
| Oren–Nayar | h = cos α·[A + B·sin α·tan α], A = 1 − 0.5σ²/(σ²+0.33), B = 0.45σ²/(σ²+0.09) | rough rock (σ = facet-slope std, rad) |
| Phong lobe | h = k_d·cos α + k_s·cos^m(2α) | wet flowstone, ice, polished calcite: glint near 0°, loss elsewhere |

For a mobile scanner, the ETH in-situ MLS method is the nearest published analogue. It fits a "global" angle function for the whole scan, or a "per-segment" one where segments ideally hold a single material, using little or no overlap ([Laasch, Medic & Wieser 2025](https://isprs-archives.copernicus.org/articles/XLVIII-G-2025/845/2025/)). Its TLS companion outputs a "configuration-independent intensity" rather than claiming true reflectance ([TU Wien](https://repositum.tuwien.at/handle/20.500.12708/218316?mode=full)). That is the honest target for dMapper too.

**Normals limit the incidence correction.** The relative error of 1/cos α is tan α·δα *(computed)*:

| α | 10° | 30° | 45° | 60° | 70° | 80° |
|---|---|---|---|---|---|---|
| Error for a 5° normal error | 0.4 % | 2.5 % | 4.4 % | 15 % | 24 % | 50 % |

Normals estimated from single-scan neighbourhoods can be badly wrong. One automotive paper measured an incidence-angle MSE of 0.44 rad ([arXiv 2401.01439](https://arxiv.org/html/2401.01439v1)). Normals should therefore come from the **final multi-pass map**: PCA of all points in a 5–15 cm surface cell after loop closure, keeping the smallest-eigenvalue vector, with a radius of a few point spacings and at least 10× the range noise (rule of thumb, *inference*). Drop observations above **60–70°** and weight the rest by cos α. A snow study even recommended 40° because of overcorrection ([Remote Sensing 2020](https://doaj.org/article/f0b92d0514a6432eaad3db7fd9351417)). Cells whose planarity is low or whose λ₃ residual is large, such as corners and speleothem clusters, have no meaningful single α and should be excluded from calibration. The footprint sets the facet scale over which the "geometric" normal differs from the facets that actually reflect, and the L2's beam divergence was not researched.

## Mist, window condensation and mixed pixels need filters, not formulas

**Clear cave air is negligible.** Two-way transmission is exp(−2γR), and with the Kim model γ = (3.91/V)·(λ/550)^(−q), where q = 0 below 0.5 km visibility ([Radioengineering 2010](https://www.radioeng.cz/fulltexts/2010/10_02_223_227.pdf)), the loss stays under about 2.5 % at 30 m for V above 10 km *(computed)*. Mist is a different matter. At V = 1 km the bias is 8 % at 10 m and 21 % at 30 m, and at V = 0.1 km intensity becomes unusable *(computed)*. Below 0.5 km visibility, fog extinction is nearly independent of wavelength, and 905 nm and 1550 nm differ by less than 10 % ([Applied Sciences 2019](https://doaj.org/article/e3d51af263e646b4ad24c22cced59866)). Nováková et al. correct explicitly for cave aerosol, which "similar to fog, considerably attenuates" the beam ([UPJŠ](https://www.upjs.sk/prirodovedecka-fakulta/en/actuality/laser-scanning-the-key-to-detecting-darkroom-surfaces/)).

In practice the operator's breath and plumes produce localised false near returns. **Condensation on the window** attenuates every return by about the same factor at all ranges. Both are better handled by the per-window gain k(t) of the self-calibration, plus rejection of isolated near returns, than by an atmospheric model *(inference)*. A window whose fitted k(t) drops sharply against its neighbours is the signature of fogging, and the gain step also gives a QC flag for the operator.

**Mixed pixels must go before calibrating.** When the footprint straddles an edge, range and intensity blend ([arXiv 2503.07472](https://arxiv.org/pdf/2503.07472)). One TLS thesis calls the edge effect one of the most serious intensity problems ([NTU thesis](https://tdr.lib.ntu.edu.tw/handle/123456789/68228?mode=full)). Near-edge range residuals correlate with intensity, incidence and spot size ([Hartmann & Neumann, FIG 2022](https://www.fig.net:443/resources/proceedings/fig_proceedings/fig2022/ppt/pe1.02/PE1.02_hartmann_neumann_11443_ppt.pdf)). With fill fraction f, the echo carries about f·ρ₁ plus a blended range *(inference)*. Five filters cover this *(inference, following the cited mechanisms)*:

- points whose distance to the map surface exceeds 2–3× the range noise;
- points in cells with high scattering or low planarity;
- points within one or two footprints of a depth discontinuity in the map;
- saturated values (255) and points below R_min;
- in narrow speleothem passages, an expected sizeable loss of points to these filters, which should be reported as a coverage fraction.

## Self-calibration in log space, anchored by a panel grid, gives a 5–15 % map

**Absolute calibration** (Kashani's Level 3) scans reference panels of known reflectance over a grid of ranges and angles. Krooks et al. used a four-step Spectralon at 99/50/25/12 % ([ISPRS Annals 2013](https://isprs-annals.copernicus.org/articles/II-5-W2/145/2013/isprsannals-II-5-W2-145-2013.pdf)), Kaasalainen et al. Spectralon, tarps, sand and gabbro ([TUNI](https://researchportal.tuni.fi/en/publications/analysis-of-incidence-angle-and-distance-effects-on-terrestrial-l/)), and Tan & Cheng a look-up table of reference targets ([ECNU](https://pure.ecnu.edu.cn/en/publications/correction-of-incidence-angle-and-distance-effects-on-tls-intensi/)). A protocol suited to the L2 *(synthesis)* uses panels of about 5–10, 25, 50 and 90–99 %, large enough to fill the footprint with margin. Ranges run 0.3, 0.5, 0.75, 1, 1.5, 2, 3, 4, 6, 8, 10, 15 and 20 m, and angles 0–70° in 10° steps at three ranges. Bright panels close in test saturation, and dark panels far away test the noise floor. Because the L2's pattern is non-repetitive, each panel should be dwelt on for several seconds and the beam direction φ logged.

**Relative self-calibration** (Level 2) needs no targets. It uses the fact that a registered survey sees each surface many times. Levinson & Thrun calibrate per-beam response from a moving platform, assuming points lie on contiguous surfaces and solving with EM-like iterations that require accurate localisation (search extract, [Levinson thesis](https://purl.stanford.edu/zx701jr9713), [CMU RISS poster](https://riss.ri.cmu.edu/education/colby-poster.pdf)). Höfle & Pfeifer fit a global correction by least squares over homogeneous areas and reduce the disturbing effects to below a noise level of about 10 % ([dissertation](https://archiv.ub.uni-heidelberg.de/volltextserver/36930/1/hoefle_dissertation_2007.pdf)). Tan & Cheng estimate the distance function from natural homogeneous targets after removing the angle effect, and cut CV by 52 % ([ECNU](https://pure.ecnu.edu.cn/en/publications/distance-effect-correction-on-tls-intensity-data-using-naturally-/)).

For dMapper *(proposed design; inference)*, each valid observation i of surface cell p satisfies

**log I_i = log g(R_i) + log h(α_i; n or σ) + log c(φ_i) + log k(t_i) + log ρ_p + ε_i**

c(φ) is a smooth gain over the beam direction in the sensor frame, standing in for the missing ring id. k(t) is a per-window gain covering drift and fogging. The fit alternates:

1. With the curves fixed, each log ρ_p is a robust (Huber) weighted mean in closed form.
2. With the ρ fixed, the spline coefficients of g, c and k, and the exponent n (or σ), come from one sparse linear least-squares solve.
3. Repeat until the change is below 0.1 %.

The scale ambiguity is fixed by setting median ρ = 1, or by a panel in the scene for absolute values. Only well-conditioned cells drive the curves: planar, n_obs ≥ 20, angular spread ≥ 20°, range spread ≥ 2×. Cells that fail these criteria still receive ρ_p from the final curves. The log form is convenient because a log-amplifier sensor becomes additive in it. Castorena's gradient-domain fusion is an alternative if sessions or units disagree ([arXiv 1611.09203](https://arxiv.org/pdf/1611.09203)).

**Per-cell aggregation** is the output. For each cell, store the robust ρ_p, its scatter (MAD across observations), n_obs, the α and R ranges covered, the fitted local n, and a validity flag. Use weights w_i ∝ cos α_i / σ²(R_i), where σ²(R) comes from the fit residuals binned by range. The scatter is both the QC metric and, later, a feature.

**Expected residual accuracy.** Survey-grade TLS reaches <3 % ([Xu 2017](https://www.mdpi.com/2072-4292/9/11/1090)), about 10 % (Höfle & Pfeifer), and CV reductions of 52–93 % on homogeneous targets ([Tan et al.](https://pure.ecnu.edu.cn/en/publications/intensity-data-correction-for-the-distance-effect-in-terrestrial-/)). For the L2, with an 8-bit value, no per-beam id, an unknown internal mapping and mostly near-field data, **5–15 % relative residual** per cell is a reasonable target, and absolute values carry the panel uncertainty on top *(inference)*. Single points will stay much noisier than cells. That is why aggregation, not per-point correction, is the deliverable.

## Implementing it in dMapper: off by default, after consistency, validated against panels

The step belongs **after `post_process`** (loop closure, then consistency) and before `save`, because only then are the poses final. It changes no pose, so with `use_radiometric_correction = false` as the default, `44_short` and the full 44 stay bit-identical with their manifests. One detail needs checking in the code: `load_data` shifts points by the lever arm, so range and beam direction must be computed from the LiDAR origin, not from the IMU origin. The output change is required in every scenario, because `save_result` today writes only world xyz, intensity and timestamp.

| Step | Work (layer) | Validation / pass criterion |
|---|---|---|
| 1 | `tools/intensity_probe.py`: histogram, 255 share, range-bin median for a picked patch, per-window median (needs numpy; ask the user to install it) | Decide raw / compensated / AGC; first R_min estimate |
| 2 | Bench tests 1–5 and the panel grid with the L2 recorded through dLidar | Measured g(R), h(α), G, warm-up drift; repeatability between days < 3 % |
| 3 | `src/domain/radiometry.{h,cpp}`: surface-cell grid (5–10 cm) from final points, PCA normals, filters, the alternating log-space fit, aggregation (Eigen only) | Unit test on `tests/synthetic_recording` with known per-patch ρ, injected g(R) with a near-field dip, cos^n, k(t) jump, edges: recovered curves and ρ within 1 % |
| 4 | Use case in `src/application` called after `post_process`; settings in a new `[radiometry]` section (`TomlIO::POINTERS` + `CATEGORIES`, golden TOML regenerated in its own commit) | Off: `44_short` bit-identical. On: `ctest` passes; time cost reported |
| 5 | Output: keep raw `intensity`; LAS extra bytes for ρ_corr, R, α, cell ρ_p, MAD, n_obs, flags; per-cell summary; g, h, c, k in the results JSON (`FolderResultSink`, `laz_export`) | Files readable in CloudCompare; curves plotted |
| 6 | Run on recording 44 s0/s1/s2 and an outdoor recording | CV of revisited homogeneous walls falls ≥50 %; the seam contrast between passes over the same wall disappears; self-calibrated g, h agree with Step 2 panels within their scatter; s0/s1/s2 ρ maps agree within the residual |
| 7 | In-cave panel at several ranges/angles, repeat survey in wet and dry season | Absolute bias against panel < 5 %; dry-wall ρ stable across seasons |

Steps 1–2 can stop the project cheaply. If the byte turns out to be AGC-switched or coarse in a way that cannot be modelled, the result is a documented negative, not a buried bug. Per CLAUDE.md, a Debug build and `ctest` belong with Step 3, because new containers and loops can behave differently there. Precision wins over speed: the fit needs a few linear passes over the points, which is small next to the odometry.

## Later: what corrected reflectivity enables

Material identification sits on top of the per-cell ρ_p and should wait for the steps above. At 905 nm the Fe³⁺ crystal-field band lies right under the laser: **848–906 nm in hematite and 909–1022 nm in goethite** ([Scheinost et al. 1998](https://www.doi.org/10.1346/CCMN.1998.0460506), [Sherman & Waite 1985](https://msaweb.org/AmMin/AM70/AM70_1262.pdf)). Iron-stained rock, ochre and red clay therefore look darker than their visible colour suggests. Carbonate features sit at 2320–2350 nm, so **limestone vs dolomite, and calcite vs gypsum, are inseparable** from a single 905 nm channel ([Kurz et al. 2012](https://isprs-archives.copernicus.org/articles/XXXIX-B5/417/2012/isprsarchives-XXXIX-B5-417-2012.pdf)). Water absorbs only about 0.068 cm⁻¹ at 900 nm ([Hale & Querry table](https://users.physics.ox.ac.uk/~pierrehumbert/PrinciplesPlanetaryClimate/Data/WorkbookDatasets/Chapter4Data/AbsorptionData/WaterAbsorptionOrig.txt)). Wetting still darkens rock through optical effects and saturates early in the VNIR ([Lobell & Asner 2002](https://oa.mg/work/10.2136/sssaj2002.7220)), so 905 nm gives a wet/dry flag rather than a moisture gauge. In a cave, wet surfaces biased intensity low ([Nováková et al. 2022](https://hal-ifp.archives-ouvertes.fr/GR-3T/insu-03752599v1)). Clearly separable pairs are expected to include bright calcite, flowstone or gypsum against basalt, coal, dark shale or clay sediment; marble vs lherzolite was shown at >84 % with corrected TLS intensity, probably at 1550 nm (Nováková 2022). Ambiguous pairs include wet limestone vs dry shale, iron-stained vs wet carbonate, fresh snow vs moonmilk, and clear ice vs wet rock. Library values at 905 nm (splib07, ECOSTRESS) could not be read and still need checking. Most outcrop results, such as Franceschi's marl/limestone r = −0.85, used 1535 nm, where clay-bound water contributes, and do not transfer quantitatively ([Franceschi et al. 2009](https://www.earth-prints.org/entities/publication/bb9c4bdf-3743-4fbd-a5b6-db80cfd4cd4d)).

For classification, the proven recipe is a random forest on corrected-intensity statistics plus multi-scale eigen features (CANUPO, 3DMASC: 91–98 % with fewer than 2,000 samples per class, [arXiv 2401.09481](https://arxiv.org/pdf/2401.09481)). Fusing spectral and geometric features raised outcrop macro-F1 from 0.65 to 0.82 ([Remote Sens. 17:2434](https://mdpi-res.com/d_attachment/remotesensing/remotesensing-17-02434/article_deploy/remotesensing-17-02434.pdf)). Validation should use spatially blocked passages. Tools include CloudCompare q3DMASC, PDAL `filters.covariancefeatures` and pgeof ([pgeof](https://pypi.org/project/pgeof/)). Expect 3–5 robust classes from intensity, more with geometry *(inference)*. The fitted per-cell angular exponent n, which tells glossy from granular surfaces, is the single-wavelength sensor's best substitute for a second channel.

## Conclusion

The decisive unknown is not the physics, which is textbook, but the L2's own signal chain: whether the byte is raw, compensated or gain-switched, and what happens below 2 m. One afternoon of bench tests answers that before any code is written. After that, dMapper's mapping-first design turns calibration from a lab exercise into a least-squares fit on revisits the survey already contains. The measure of success is a wall that reads the same from every pass, not a pretty colour map. The first code change costs nothing in precision and unlocks everything after it: keep range, incidence angle and raw intensity for every output point.
